PII never leaves
your device. Surrogates do.

SurrogateShield finds the personal data in a message, replaces it with realistic, consistent surrogates before the request reaches an LLM provider, and puts the real values back in the reply. On 3,677 personal values placed in real ShareGPT, WildChat and oasst1 messages it let 0.8% through. GLiNER-PII let through 9.1%, Microsoft Presidio 31.6% and LLM Guard 56.3%. It trailed on only a few tests, listed in one line under Limitations. The surrogate map is encrypted with AES-256-GCM and stays on your machine. Ships as a Python library with a CLI, plus an interactive terminal app.

01 / PIPELINE
How it works

A single round-trip through the proxy, end to end.

Every message goes through detection, surrogate generation, an encrypted map, the LLM call and restoration. Detected values are replaced before the request is made. If a detection model is missing, mask() raises DetectorUnavailable and the text is not sent half-masked.

01
Service-query router

With address_mode="auto" (the default), a question that needs a location to be answered (e.g. pharmacies near…) keeps the street and city and shifts the house number by ±1. If the question is about a sensitive topic (HIV, abortion, rehab, therapy, mental health, shelter, immigration and similar), the street becomes my area. Every other address is replaced in full.

02
SentinelLayer detection

PatternScan finds structured values with regex and validators. The canonicaliser also reads them when they are written in words, spelled out or disguised with look-alike characters. EntityTrace (spaCy) and PIITagger (a fine-tuned DeBERTa-v3-small) find names, organisations, places, addresses, handles and IDs. Structural passes then read CSV columns, signatures and “my name is” frames. A relation gate keeps public figures and companies you only mention.

03
MimicGen

Draws a surrogate of the same type and shape for each value: real-looking names, an e-mail built from the surrogate name, a phone in the same format, Luhn-passing card numbers, IDs with the same letter and digit pattern. A value gets the same surrogate every time it appears in a session, and no two values share one.

04
ShadowMap

The {surrogate → original} pairs are kept in memory by default. When saved, they are encrypted with AES-256-GCM under a per-session key derived with HKDF-SHA256 from a 32-byte device secret. The file cannot be read without that secret.

05
LLM API

Receives the masked text over HTTPS: the prompt, the earlier turns and any RAG context, each with its detected values replaced. On real chat text 0.8% of placed values reached it, against 9.1% for GLiNER-PII and 31.6% for Presidio.

06
ResolvePass

Three-tier substitution on the response: exact match → component match (handles partial name mentions) → fuzzy match (rapidfuzz score ≥ 85). Restores originals before the user sees anything.

Service-query handling. In a message like "restaurants near 1126 E Apache Blvd, Tempe, AZ", the house number is shifted by ±1 and the street and city are kept, because replacing the address would make the answer useless. Sensitive topics (HIV, abortion, rehab, addiction, mental health, therapy, domestic violence, shelter, immigration, self-harm and others) coarsen the street to my area instead. Turn the feature off with service=False. The benchmark redraws every address, so these kept parts are not part of its leak figures.
02 / DETECTION
SentinelLayer

Patterns, two models, structure. One answer per value.

On the default balanced preset, the stages run in this order: PatternScan with the canonicaliser, EntityTrace, PIITagger, then the structural passes. A relation gate keeps names that are not tied to the writer, and a resolver settles each value on one type. Removing any stage raises the leak rate. Without the pattern rules it goes from 0.8% to 1.4%, without the canonicaliser to 3.9%, and without the tagger to 10.8%.

STAGE 01

PatternScan

pattern_scan.py · canonical.py

Regex with format validators: Luhn for cards, checksums for IBANs, VINs and routing numbers, and range checks for SSNs and ZIPs. The canonicaliser reads the same message in other written forms, such as numbers in words, “at”/“dot” e-mails, ordinal dates and look-alike or zero-width characters. A value found that way gets its surrogate written back in the same form.

methodregex + validators + views
coversemail · phone · URL · IP · MAC · card · IBAN · SSN · passport · VIN · API key · crypto · DOB · age · ZIP
viewsworded · spelled · dates · folded · joined
STAGE 02

EntityTrace

spaCy · en_core_web_lg

Named-entity recognition with spaCy. In balanced it reads places only, because its names cost more harmless edits than they find, so names come from the tagger. In strict and classic it reads names too and sends borderline spans to ContextGuard. The fast preset skips it, and the tagger reads places instead.

confirmed≥ 0.90
borderline0.70 – 0.90
fallback0.75 (CG off)
STAGE 03

PIITagger

DeBERTa-v3-small · pii-tagger-dv3s-40k

A token tagger fine-tuned for personal data. It reads names, organisations, places, addresses, phones, handles, IDs and credentials, and long text is read in overlapping windows. The weights (~565 MB) are on Hugging Face: they download once, at a fixed commit, must match their SHA-256 pin, and then load from the local cache with no network. If they cannot be fetched, mask() raises DetectorUnavailable instead of sending the text with less protection. The classic preset runs without it.

window256 tokens · stride 64
weightsHugging Face · sha256-pinned
servernone, in-process

Passes after the models detection/pipeline.py · structural.py · relation_gate.py · resolver.py

PassBehaviour
SStructure-driven detection. It covers CSV columns, chat speakers, signatures, “my name is” / “lives in” frames, payees after “PAYMENT TO”, and streets written the French or Portuguese way. Each rule needs its own structural evidence, so none of them fires on a bare word.
A · E · HStructural ORG (<name> Inc / LLC / Corp…), structural PERSON in all-lowercase or all-caps text, and the card brand written right before a card number.
F · G · B · CDrops implausible ORGs, merges adjacent name pieces, turns an ORG that matches an e-mail username into a PERSON, and removes a surname already inside a detected full name.
RRelation gate. An organisation or place is replaced only when it is tied to the writer (“I work at…”, “my son’s school…”). Public figures, public companies and places that are only the topic of a question are kept.
resolverOne candidate per value. Source priority is applied first, then a rule for each type conflict, then the score.
CGContextGuard (dslim/distilbert-NER) checks borderline spaCy spans. It is off in balanced and fast, and on in strict and classic.

Quasi-identifier scorer per Sweeney (2000) k-anonymity

Flags combinations of fields that together can re-identify a person. The result is logged with the detections, and the terminal app shows a warning. The scorer does not change what gets replaced.

04 / GENERATION
MimicGen

Realistic surrogates, not [PLACEHOLDER] tokens.

Every surrogate has the same type and shape as the value it replaces, and stays the same for the whole session. Fake names look like names, a fake card passes Luhn, and a fake IBAN passes its checksum. The model reads a coherent message and writes a coherent reply, and that reply can be restored. Placeholder tools such as Presidio and GLiNER-PII send [PERSON] instead.

05 / COMPARISON
Head to head · six other tools

Fewer leaks than every tool we tested. Fewer harmless edits too.

All tools ran on the same real ShareGPT, WildChat and oasst1 user messages, with the same scorer. The messages were sealed until the detector was final. 3,677 personal values were placed in 1,308 messages. SurrogateShield let 30 of them (0.8%) reach the provider. The others let through: GLiNER-PII tuned to 0.3, 7.3%; GLiNER-PII at its default 0.5, 9.1%; Microsoft Presidio, 31.6% (with Faker, the same); Presidio with the obi/deid_roberta_i2b2 transformer, 54.0%; LLM Guard, 56.3%. That is 11× fewer leaks than GLiNER-PII and 39× fewer than Presidio. The difference from GLiNER-PII is −8.3 points, with a 95% interval of [−9.3, −7.3]. Commands and every split: bench/results.

07 / ADVERSARIAL
Attacker experiment

Can an attacker model recover the originals?

claude-opus-5-5 was given the text each tool sent to the provider for 180 real prompts holding 636 placed values. It was told that a filter may have replaced some values, changed parts of others or left them alone, and asked to give back every original. A value counts as known if the tool left it in plain text or the attacker named it letter for letter. SurrogateShield let the attacker know 1.8% of the values. GLiNER-PII let it know 12.6%, Presidio 34.2% and LLM Guard 61.0%.

SURROGATESHIELD

The fewest values known, by far

  • Known letter for letter: 1.8% (11 of 627)
  • Left in plain text: 7 of 636
  • Recovered exactly: 4 of 620, all of them URLs
  • Across whole conversations: 1 of 177 recovered, 3 of 179 known
THE OTHER TOOLS

Most of the loss is text left in place

  • GLiNER-PII: 12.6% known (79 of 629), 73 left in plain text
  • Presidio: 34.2% known (215 of 629), 201 left in plain text
  • Presidio + Faker: 33.2% known (209 of 629)
  • LLM Guard: 61.0% known (383 of 628), 364 left in plain text

08 / SECURITY
Cryptographic design

Local-only key material. AES-256-GCM on every write.

The map from surrogates back to your values is kept on your machine. In the library it lives in memory unless you give it a directory. On disk it is sealed with a key derived from a device secret that is never sent anywhere, and a file that will not decrypt raises an error instead of quietly becoming an empty map.

KEY MATERIAL

Device secret + per-store derivation

  • 32 random bytes at ~/.surrogateshield/device.key, created once
  • File mode 0600, home directory 0700
  • Per-store key: HKDF-SHA256, device secret as input, store id as salt, file kind as info
  • If the secret cannot be saved, an error is raised rather than using a throwaway key
SHADOWMAP

Sealed surrogate ↔ original store

  • Format: SSv1 ‖ nonce (12 B) ‖ AES-256-GCM, fresh nonce on every save
  • Kind and id are bound in as associated data, so a file only opens as what it was written for
  • Atomic writes: temp file, fsync, rename
  • Undecryptable file → moved aside, CorruptStoreError raised
TRANSMISSION

What goes over the wire

  • Detected values are sent over HTTPS as surrogates
  • Conversation history is sealed the same way as the ShadowMap
  • RAG documents go through SentinelLayer before they are indexed
  • Missing tagger weights raise DetectorUnavailable; nothing is sent half-checked
.GITIGNORE

What is excluded by default

  • conversations/ and *.shadowmap — history and sealed maps
  • *.key, .surrogateshield/ — the device secret
  • .env — API keys
  • Raw benchmark data and live-run outputs

Quick start

Up and running in a few commands.

Activate a virtual environment before installing. Installing into the system or base conda Python is the most common cause of "package not found" errors at runtime. Then run surrogateshield doctor: it checks that every detection stage loads before you send anything.

terminal · bash installation 
# Clone
$ git clone https://github.com/sherwinvishesh/SurrogateShield.git
$ cd SurrogateShield

# Create and activate a virtual environment  ← required

$ source .venv/bin/activate           # Windows: .venv\Scripts\activate

# App + library (editable) + benchmark dependencies
$ pip install -r requirements.txt

$ python -m spacy download en_core_web_lg

# Set your API key and launch the terminal app

13 / LIBRARY
Standalone package

The whole engine, in pip install ./python-library.

No dashboard, just the detection and masking engine as a Python API. The package is self-contained: it imports nothing from the terminal app, which is built on top of it. Use a Session per conversation, or the module functions for a quick script. It is the same engine that leaked 0.8% on real chat text, against 9.1% for GLiNER-PII and 31.6% for Presidio.

terminal · bashinstall
# From the repository root
$ pip install ./python-library
$ python -m spacy download en_core_web_lg

# Optional: Rich colour tables for detected PII / surrogates
$ pip install "./python-library[display]"

# Optional: fetch the PIITagger weights now (else on first use)
$ surrogateshield download

# Check that every stage loads
$ surrogateshield doctor
Models. The default preset, balanced, needs spaCy's en_core_web_lg and the PIITagger weights, sherwinvishesh/surrogateshield-pii-tagger on Hugging Face (~565 MB, MIT). The weights download once on first use, or with surrogateshield download, and are checked against their SHA-256 pin; a folder of the same name under $SURROGATESHIELD_MODELS is used instead when there is one. If either model is missing or cannot be fetched, mask() raises DetectorUnavailable and sends nothing. On a machine without the tagger weights, use preset="classic".

FunctionDescription
shield.Session(id, *, config, storage_dir, seed)Masking state for one conversation. Use it as a context manager; amask / aunmask / ascan for asyncio

Quick start — a full round-trip

python · claudemask ▸ call ▸ unmask
import anthropic
import surrogateshield as shield

client = anthropic.Anthropic()

text = (
    "Hi, I'm Priya Raman. Email me at priya.raman@northwind.io or call "
    "+1 415 555 0142. My order NW-48213-K hasn't arrived at 1847 Alder "
    "Street, Portland. Can you draft a complaint to Northwind Outfitters?"
)

with shield.Session() as s:
    sanitized = s.mask(text)
    # → "Hi, I'm Adya Nath. Email me at adya.nath@vance.io or call
    #    +1 213 581 8333. My order VW-02898-Z hasn't arrived at 6237
    #    James Street, Olympia. Can you draft a complaint to Northwind
    #    Outfitters?"   (surrogates differ per run; pass seed= to fix them)

    response = client.messages.create(
        model="claude-sonnet-5-5", max_tokens=1024,
        messages=[{"role": "user", "content": sanitized}],
    )

    # unmask() takes the SDK object directly and puts your values back
    print(s.unmask(response))   # the letter is signed "Priya Raman"
# leaving the block discards the map

The provider receives the surrogates for every value the detector found; the answer you see has your own values back. The company you are complaining to is kept, because it is only mentioned. The same flow works with OpenAI, Gemini and local Ollama models; unmask() detects the response format.

INSPECT

scan() — detect without masking

Runs the full pipeline and returns each detection with its offsets, type, score and the stage that found it. It never changes the text or the session's map.

  • masked=False marks a value kept by pii_off
  • pii_finder alias for data-pipeline readability
  • Pre-warm the models with shield.Session().scan("warm up")
PRESETS

Pick the trade-off

shield.config(detection="fast"), or SURROGATESHIELD_PRESET in the environment. Benchmark leak and median time per message:

  • balanced (default) — 0.8%, 47.1 ms
  • fast — 0.8%, 38.2 ms, no spaCy
  • strict — 0.2%, 67.1 ms, edits far more harmless text
  • classic — 2.5%, 29.2 ms, no tagger weights needed
PERSISTENT

Encrypted disk shadow map

The default is in memory. Give a directory and the map persists across processes, sealed with AES-256-GCM, for web servers and multi-worker setups.

  • shield.Session("user-42", storage_dir="/var/app/maps")
  • The same id reopens the same map
  • Key derived from the device secret (HKDF-SHA256), file mode 0600
  • flush() or close() deletes the .shadowmap file
PORTABLE

Any provider, any object

unmask() reads Anthropic, OpenAI and Gemini response objects and dicts, and plain strings from local models.

  • Anthropic Message · OpenAI ChatCompletion · Gemini response
  • Multi-turn: the session map lives across turns
  • 13 public types, the same pipeline as the terminal app

Multi-turn conversations

Keep two histories: one in surrogates for the API, one with your values for display. The session map lives across turns, so a surrogate made in turn 1 still resolves in turn 5. On the benchmark's 60 conversations, SurrogateShield put back 81 of 82 values; Presidio + Faker and GLiNER-PII put back none.

python · openaitwo histories, one session
from openai import OpenAI
import surrogateshield as shield

client = OpenAI()
session = shield.Session()
api_history, display_history = [], []   # surrogates vs your values

def chat(user_input):
    sanitized = session.mask(user_input)
    api_history.append({"role": "user", "content": sanitized})
    display_history.append({"role": "user", "content": user_input})

    response = client.chat.completions.create(
        model="gpt-4o-mini", messages=api_history,
    )
    raw = response.choices[0].message.content   # surrogate text
    restored = session.unmask(response)          # your values

    api_history.append({"role": "assistant", "content": raw})
    display_history.append({"role": "assistant", "content": restored})
    return restored

chat("My name is Priya Raman and I live at 1847 Alder Street, Portland.")
print(chat("What was the address I mentioned earlier?"))
# → "1847 Alder Street, Portland", restored from turn 1's map
session.close()

unmask() — three reconstruction passes

Each pass only runs on surrogates the previous one did not resolve, so partial matches never corrupt unrelated text.

PassMethodHandles
1exact replacementSurrogate appears verbatim in the response — the vast majority of cases
2component matchingMulti-word surrogate used partially (the model wrote "Adya" from "Adya Nath") — scoped to unresolved surrogates only
3fuzzy · rapidfuzzpartial_ratio ≥ fuzzy_threshold (default 85) — reformatted casing, added punctuation, minor edits

SERVICE QUERIES

Proportional address protection

A question like "find a coffee shop near 99 Market Street" would be useless with a random fake address. With address_mode="auto" (default), a service query keeps the street and city and shifts the house number by ±1.

  • House number shifted, street and city kept
  • Sensitive topics (HIV, abortion, rehab, therapy, shelter, immigration…) turn the street into my area
  • Any other message: a full fake address of the same shape
  • shield.config(service=False) or address_mode="replace" to always replace

TROUBLESHOOTING

Common adjustments

  • DetectorUnavailable? Run surrogateshield doctor; it names the missing model
  • Slow first call? Models load lazily — pre-warm with shield.Session().scan("warm up")
  • Need it faster? shield.config(detection="fast"): same leak rate on the benchmark, no spaCy
  • Surrogate not restored? Lower fuzzy_threshold toward 75 to recover heavily reformatted values
  • distilbert (~250 MB) downloads once to ~/.cache/huggingface/ when ContextGuard is on
Tested with no API key. pytest tests python-library/tests covers the package end to end: detection, surrogates, ShadowMap memory and disk modes, the response parser, pii_off, presets, ResolvePass, the CLI and the public API.
